# 정책 보고서 작성 표준

정책 보고서는 읽는 사람(공무원·국회·위원회)이 **결론 → 근거 → 실행 방법** 순서로 3분 안에 판단할 수 있어야 한다. 이 스킬의 최우선 원칙은 **틀린 정보 0건**이다. 문장이 매끄러운 것보다 숫자 하나가 정확한 것이 중요하다.

## 1. 절대 규칙 (위반 시 재작성)

1. **출처 없는 수치·사실 금지.** 모든 숫자, 법 조문, 사례, 인용문에 출처를 단다. 찾지 못한 값은 지어내지 말고 `[확인 필요: 무엇을, 어디서]`로 남긴다.
2. **1차 출처 우선.** 법령은 법령 원문, 통계는 작성 기관 원자료, 국제 규정은 원문을 인용한다. 기사·블로그·2차 요약은 1차 출처를 못 찾았을 때만 쓰고 `(2차 출처)`라고 표시한다.
3. **법령은 정확히 특정한다.** 법령명 + 조·항·호 + 시행일(또는 개정일)까지 적는다. 형식: `「○○법」 제○조제○항제○호 (시행 YYYY.MM.DD)`. 조문 번호와 내용은 원문을 직접 확인한 뒤에만 쓴다.
4. **통계는 기관·기준연도·단위를 함께 적는다.** 예: `통계청 KOSIS, 2024년 기준, 단위: 천 톤`. 연도가 다른 통계끼리 바로 비교하지 않는다.
5. **추정치는 계산식을 공개한다.** `추정 시장 규모 = 대상 사업장 수 × 평균 처리량 × 단가` 형태로 가정과 출처를 함께 적고, 본문에 `(추정)`이라고 표시한다.
6. **확인한 것과 추정한 것을 섞지 않는다.** 확정 수치, 추정치, 업체 주장치(자사 실험값 포함)를 구분해 표기한다. 자사 실험값은 `(자사 시험, 시험기관·일자)`로 적는다.
7. **웹 검색으로 출처에 접근하지 못하면 숨기지 말고 채팅에서 알린다.** 접근 못 한 출처를 기억에 의존해 인용하지 않는다.

## 2. 작업 순서

### 1단계: 요건 확인 (작성 전에 묻기)
아래 중 모르는 항목만 묻는다. 이미 대화에 있으면 다시 묻지 않는다.

| 항목 | 확인 내용 |
|---|---|
| 수신처 | 어느 부처·국회·지자체·위원회에 내는가 |
| 목적 | 제도 신설 / 규제 개선 / 예산 반영 / 실증 사업 / 정보 제공 |
| 문서 유형 | 정책 보고서(10~20쪽) / 정책 브리프(2쪽) / 규제 개선 건의서 |
| 공개 범위 | 대외 제출용인지 내부 검토용인지 (원가·내부 사정 포함 여부가 달라짐) |
| 보유 자료 | 이미 가진 실험 데이터, 견적, 기존 보고서 |

### 2단계: 근거 수집
- `references/sources.md`의 공식 출처 목록에서 먼저 찾는다.
- 수집한 근거는 본문 쓰기 전에 **근거 표**로 정리해 사용자에게 보여 준다.

| 번호 | 주장 | 수치/내용 | 출처 (기관, 문서명, 연도, 쪽/조문) | 구분 (확정/추정/자사) |
|---|---|---|---|---|

### 3단계: 목차 확정 → 4단계: 본문 작성 → 5단계: 검증 (아래 체크리스트) → 6단계: 출력

## 3. 표준 목차

### A. 정책 보고서 / 정책 제안서
1. **요약 (1쪽)**: 결론과 요청 사항을 첫 줄에. "무엇을, 누가, 언제까지, 얼마로" 형식
2. **추진 배경**: 왜 지금 필요한가 (정책 환경 변화, 국제 동향, 법 개정 일정)
3. **현황 및 문제점**: 수치로 보여 준다. 문제마다 원인을 같이 적는다
4. **국내외 사례**: 해외 제도·실증 사례. 국가, 제도명, 시행 연도, 성과 수치
5. **정책 대안 비교**: 최소 2개 이상의 대안을 아래 표로 비교

   | 대안 | 효과 (정량) | 소요 예산 | 실행 가능성 | 리스크 | 종합 |
   |---|---|---|---|---|---|

6. **권고안**: 선택한 대안과 선택 이유. 필요한 법령 개정 조문, 소관 기관
7. **실행 로드맵**: 단계별 일정 표 (연도·분기 단위), 단계별 소요 예산
8. **기대 효과**: 정량 효과 우선 (감축량, 비용 절감, 일자리 등). 계산식 포함
9. **리스크 및 대응**: 리스크마다 발생 가능성, 영향, 대응 방안
10. **참고문헌**: 번호순, 본문 번호와 일치

### B. 규제 개선 건의서
| 현행 규정 (조문 원문) | 문제점 | 개선안 (개정 문구 예시) | 근거 (사례·수치) | 기대 효과 |
|---|---|---|---|---|

조문 단위로 한 행씩 쓴다. 개정 문구는 신구조문 대비표 형식으로 붙인다.

### C. 정책 브리프 (2쪽)
핵심 메시지 1줄 → 문제 수치 3개 → 제안 3개 → 기대 효과 1개 표 → 출처. 그림 또는 표 1개 이상.

## 4. 문장·표기 규칙

- **개조식**으로 쓴다. 명사형 종결(`~함`, `~필요`, `~추진`). 서술형 종결(`~이다`, `~있다`) 금지.
- **결론을 먼저** 쓴다. 각 절의 첫 줄은 그 절의 결론.
- **약어·전문용어는 처음 나올 때 괄호로 풀이**한다. 예: `CCU(탄소 포집·활용)`, `NCC(나프타 분해 설비)`.
- 숫자는 단위와 기준 시점을 함께 쓴다. `약`, `상당한`, `크게`처럼 크기를 흐리는 말 대신 수치를 쓴다.
- 문장 중간에 em dash(`—`)를 쓰지 않는다. 콜론이나 괄호로 대체한다.
- 기계적으로 쓴 티가 나는 표현을 쓰지 않는다: `~라고 할 수 있다`, `다양한`, `혁신적인`, `획기적인`, `시사하는 바가 크다`, `귀추가 주목된다`, `~의 중요성은 아무리 강조해도 지나치지 않다`.
- 표·도표를 적극적으로 쓴다. 수치 비교는 표, 추세는 선 그래프, 구성비는 막대 그래프. 그래프마다 출처를 아래에 적는다.
- 제출용 문서에 작성자용 메모, 작업 이력, 내부 사정을 넣지 않는다. 그런 설명은 채팅에만 적는다.

## 5. 제출 전 검증 체크리스트

작성을 마치면 아래를 하나씩 확인하고, 결과를 채팅에 표로 보고한다.

- [ ] 본문의 모든 수치에 출처 번호가 있음
- [ ] 참고문헌 번호와 본문 번호가 일치함
- [ ] 법령 조문 번호·시행일을 원문과 대조함
- [ ] `[확인 필요]` 남은 항목 목록을 채팅에 따로 정리함
- [ ] 추정치에 `(추정)` 표시와 계산식이 있음
- [ ] 자사 실험값과 공인 통계를 구분 표기함
- [ ] 같은 항목에 서로 다른 수치가 있으면 불일치를 적고 채팅에 알림
- [ ] 요약 1쪽만 읽어도 요청 사항이 보임
- [ ] 대안이 2개 이상이고 비교 기준이 같음
- [ ] 약어 첫 등장 시 괄호 풀이가 있음
- [ ] em dash(`—`), 금지 표현이 남아 있지 않음

## 6. 출력 형식

- **Word(.docx)**: 화우나노텍 문서라면 `hwawoo-doc-format` 스킬의 서식 표준을 그대로 따른다. 그 외에는 `docx` 스킬을 쓴다.
- **인포그래픽 요약**이 필요하면 `hwawoo-infographic` 스킬을 쓴다.
- 파일명은 `YYMMDD_문서명` 형식. 예: `261010_강알칼리폐수_CCU_정책제안서.docx`
- 별도 요청이 없으면 **근거 표(2단계)를 먼저 보여 주고 확인받은 뒤** 본문을 작성한다.
