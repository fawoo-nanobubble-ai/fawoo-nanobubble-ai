# deeper — 프롬프트를 전문가 버전으로 깊게 다시 쓰기

이 안내 스킬은 **리본랩스가 한국어로 새로 쓴 것**이다. 생각의 출처는 앤트로픽의 Felix Rieseberg 가 2026-10-13 개인 블로그에 올린 글 「How to be more ambitious: a tutorial for humans with models」(felixrieseberg.com)이고, 같은 생각을 영어 스킬로 옮긴 것은 Dan McAteer 의 `be-ambitious`(github.com/DannyMac180/skills · MIT)다. 앤트로픽이 낸 공식 스킬이 아니다. 리본랩스는 두 사람과 제휴 관계가 없다(2026-11-04 확인).

## 언제 쓰나

- 사용자가 할 일을 한 줄로 던졌는데, 그대로 하면 겉핥기로 끝날 것 같을 때
- 사용자가 「딥퍼」·「더 깊게」·「전문가 버전으로」라고 말하며 프롬프트를 붙였을 때
- 사용자가 아무것도 붙이지 않았으면 **이 대화에서 가장 최근에 시킨 일**을 대상으로 삼는다

## 원칙 — 더 크게가 아니라 더 깊게

- 목표와 범위는 그대로 둔다. 할 일을 늘리거나 결과물 개수를 키우지 않는다.
- 같은 결과를 **더 높은 기준**으로 낸다 — 더 나은 출처, 더 날카로운 방법, 더 확실한 확인.
- 고칠 것 하나를 고치는 대신 **그 일이 원래 지키려던 상태**를 본다. 「이 버그 고쳐」보다 「이 앱이 버그 없이 돌게 지켜」가 한 단계 위다.

## 순서

1. **분야부터 이름 붙인다.** 이 일이 어느 분야의 일인지 한 줄로 적는다(예: 웹 성능 점검, 투자 보고서, 채용 공고 분석).
2. **네 가지를 먼저 답한다.**
   - 그 분야 최고 전문가라면 **시키지 않아도 여기서 할 일**은 무엇인가
   - 남이 이미 정리해 둔 요약 말고, **가장 날것의 출발 자료**는 무엇인가(원본 기록, 원 데이터, 원문)
   - 그 사람이 쓸 **구체적인 방법과 도구**는 무엇인가
   - 나나 사용자 말고, **결과가 맞는지 보여줄 바깥의 확인 수단**은 무엇인가(시험, 측정, 원 출처 대조)
3. **프롬프트를 다시 쓴다.** 위 네 가지를 담아, 사용자가 그대로 복사해 쓸 수 있게 코드블록 하나로 낸다.
4. **멈춘다.** 다시 쓴 프롬프트를 실행하지 않는다. 사용자가 「이대로 해 줘」라고 할 때만 실행한다.

## 지킬 것

- 모르는 도구·자료를 지어내지 않는다. 확실하지 않으면 「확인 못 함」이라고 적고, 확인할 방법을 같이 적는다.
- 사용자의 목표를 바꾸지 않는다. 더 큰 일을 제안하고 싶으면 다시 쓴 프롬프트 **밖에** 한 줄로만 적는다.
- 결과를 약속하지 않는다. 깊게 다시 쓴 프롬프트는 더 나은 결과의 **가능성**을 높일 뿐이다.

## 예시

사용자: 「체크아웃 페이지가 지난주부터 느려졌어. 왜인지 알아봐 줘」

- 분야: 웹 성능 점검
- 전문가라면 할 일: 느려진 것을 먼저 **재현**하고, 언제부터인지 배포 기록과 맞춰 본다
- 날것의 자료: 요약 대시보드가 아니라 실제 요청 기록(트레이스)과 서버 로그
- 방법과 도구: 프로파일러로 구간별 시간 재기, 같은 조건으로 부하 시험
- 바깥 확인: 고친 뒤 같은 부하 시험에서 숫자가 지난주 전으로 돌아오는가

그다음 이 다섯 줄을 담은 프롬프트를 코드블록으로 낸다.
