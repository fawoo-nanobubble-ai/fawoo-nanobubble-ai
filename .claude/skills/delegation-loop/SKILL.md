# delegation-loop — 반복 업무를 플레이북으로 넘기는 3단계 루프

반복하는 일 하나를 골라 **인터뷰 → 툴박스 → 검증** 순서로 플레이북을 만든다. 결과물은 `.claude/skills/[job-name]/` 폴더 하나다. Claude Code가 이 폴더를 스킬로 자동 인식하므로, 다음부터는 "[job-name] 돌려줘" 한 줄이면 된다.

핵심 규칙 하나: **결과가 틀리면 결과물을 고치지 말고 플레이북을 고친 뒤 다시 돌린다.**

## 언제 쓰나

- 사용자가 반복하는 일을 넘기고 싶다고 할 때
- 이미 있는 job 스킬이 틀린 결과를 냈다고 보고받았을 때 → 채팅에서 결과만 고치지 말고 SKILL.md / 툴박스 파일 / 검증 항목 중 원인이 된 곳을 고친다
- **쓰지 않는다**: 일회성 작업, 사용자가 직접 3번 미만 해본 일(본인도 규칙을 아직 모른다)

## 폴더 구조

```
.claude/skills/
├── delegation-loop/            ← 이 스킬 (마스터 루프, 평소엔 읽기 전용)
│   ├── SKILL.md
│   └── files/
│       ├── 01-interview-prompt.md
│       ├── 02-toolbox-prompt.md
│       ├── 03-proof-prompt.md
│       ├── job-skill-template.md
│       └── INDEX.md
└── [job-name]/                 ← 일 하나당 폴더 하나 (delegation-loop 안에 넣지 않는다)
    ├── SKILL.md                ← 그 일의 플레이북
    └── files/                  ← 툴박스: 템플릿·스크립트·체크리스트
        └── INDEX.md
```

## 순서

### 1단계 — 인터뷰 (`files/01-interview-prompt.md`)

1. job 이름을 kebab-case로 정한다(예: `weekly-ai-visibility-report`, `ccu-quote-draft`). 기존 스킬 폴더명과 겹치면 다른 이름을 쓴다.
2. 한 번에 **질문 하나**만 하고 답을 기다린다. **최소 8개**. 아래 8개 주제를 모두 다룬다.
   1. 이 일을 시작하게 만드는 계기, 빈도
   2. 입력물과 각각의 **정확한 위치**(파일 경로, 드라이브 폴더, 메일 라벨 등)
   3. 실제로 하는 순서대로의 단계
   4. 중간에 내리는 판단과 그 판단의 기준
   5. 끝났다고 말하기 전에 확인하는 것
   6. 예전에 잘못됐던 예외 상황
   7. 결과물이 맞춰야 하는 톤·기준
   8. 나쁜 결과물은 어떻게 생겼나
3. 사용자가 "끝" / "됐어" / "we are done"이라고 하기 전에는 **파일을 쓰지 않는다**.
4. 끝나면 `files/job-skill-template.md` 뼈대로 `.claude/skills/[job-name]/SKILL.md`를 쓴다. frontmatter의 `description`에는 사용자가 실제로 이 일을 시킬 때 쓰는 말을 넣는다(그래야 자동 호출된다).
5. SKILL.md 전체를 보여주고 **정확히 두 가지만** 묻는다.
   - 내가 틀리게 적은 것은?
   - 당신이 말 안 해준 것은?
   답을 SKILL.md에 반영한다.

### 2단계 — 툴박스 (`files/02-toolbox-prompt.md`)

6. 실제로 한 번 돌린다. 다시 쓸 템플릿·스크립트·메일·체크리스트가 나오면:
   - `[job-name]/files/`에 **설명적인 이름**으로 저장(날짜·버전 번호 금지. `quote-template.md` O, `quote_v2_1106.md` X)
   - 구체 값은 `[대괄호 자리표시]`로 바꾸고, 아래에 **채운 예시 하나**를 남긴다
   - SKILL.md에서 그 파일이 필요한 단계가 파일명을 가리키고, 언제 쓰고 언제 쓰지 않는지 적는다
   - `[job-name]/files/INDEX.md`에 한 줄 추가: 파일명 | 용도 | 저장일
7. 바로 **처음부터 다시** 돌린다. 저장된 파일 중 무엇을 썼고, 무엇을 처음부터 다시 만들었는지 보고한다. 다시 만든 것 = 다음 툴박스 후보.

### 3단계 — 검증 (`files/03-proof-prompt.md`)

8. job SKILL.md에 **완료 기준(Definition of done)** 5~10개를 넣는다. 각 항목은 내 의견이 아닌 **바깥 증거**로 확인 가능해야 한다: 원본 파일까지 추적한 숫자, 열리는 링크, 렌더링 스크린샷, 통과한 테스트, 원문 인용 대조, 개수, 기준 파일과의 값 비교. "명확한", "전문적인", "고품질" 같은 말은 금지.
9. 이후 이 job은 **사용자에게 보여주기 전에** 매번:
   1. 모든 항목 점검 → 2. 실패 수정 → 3. 재점검 → 4. 항목별 한 줄 pass/fail + 사용한 증거 → 5. 확인 못 한 항목은 "확인 못 함 + 이유"로 따로 적는다(통과로 치지 않는다)

## 판단 규칙

- 사용자가 이 일을 3번 미만 해봤다 → 멈추고 "아직 굳은 절차가 없다"고 말한다. 대신 다음 3번을 옆에서 같이 하며 기록하자고 제안한다.
- 결과물이 일회성이거나, 비밀번호·API 키·타인 개인정보(이력서, 신분증, 고객 연락처)를 담았거나, 사용자가 승인 안 한 초안이다 → 툴박스에 **저장하지 않는다**. 예외 없음.
- 첫 점검에서 완료 기준 3개 이상 실패 → 결과물을 땜질하지 않는다. 멈추고 절차의 어느 부분이 원인인지 보고한다.
- 사용자가 채팅으로 "이거 틀렸어"라고 한다 → 원인이 된 곳(SKILL.md 단계 / 툴박스 파일 / 완료 기준)을 고치고 다시 돌린다. 결과물 하나만 고치고 끝내지 않는다.
- 파일을 쓸 수 없는 환경이다 → 쓴 척하지 않는다. 전체 내용을 채팅에 출력하고, 정확한 파일명과 위치를 적고, 예전 사본을 지우고 교체하라고 알린다.
- 클라우드 세션에서 만들었다 → 커밋·푸시해야 남는다. 컨테이너는 세션이 끝나면 사라진다.

## 이 스킬 자체의 완료 기준

1. `.claude/skills/[job-name]/SKILL.md`가 있고 frontmatter(name, description)와 7개 섹션(목적 / 언제 쓰나 / 입력 / 단계 / 판단 규칙 / 완료 기준 / 예외 상황)이 모두 있다 — 증거: 파일 전체를 사용자에게 보여줌
2. 인터뷰가 8개 주제를 모두 다뤘고 질문이 8개 이상이다 — 증거: 대화 기록의 질문 목록
3. 사용자가 두 마무리 질문에 답했고 SKILL.md에 반영됐다 — 증거: 변경 diff
4. 툴박스 파일이 모두 `[job-name]/files/`에 있고, 이름에 날짜·버전이 없고, 자리표시 + 채운 예시가 있다 — 증거: `ls` 결과 + 파일 하나 열어 보임
5. job SKILL.md가 툴박스 파일을 이름으로 가리킨다 — 증거: `grep`으로 파일명 검색
6. `files/INDEX.md`가 툴박스 파일 1개당 1줄이고 자기 자신은 빠져 있다 — 증거: INDEX 행 수와 `ls files/` (INDEX.md 제외) 개수 일치
7. 두 번째 처음부터 실행에서 저장된 파일을 다시 썼다 — 증거: "사용 / 새로 만듦" 보고
8. 완료 기준이 5~10개이고 각각 증거 수단이 적혀 있으며 모호한 품질 단어가 0개다 — 증거: job SKILL.md의 완료 기준 섹션에서 `명확|전문적|고품질|깔끔` 검색 결과 0건

## 예외 상황

- 사용자가 인터뷰 대신 업무 설명서를 붙여넣는다 → 설명서는 **입력물**이지 규칙이 아니다. 그래도 인터뷰한다.
- 입력물이 Claude가 못 닿는 곳에 있다(개인 메일함, 로컬 PC 전용 파일) → 먼저 닿는 위치(레포 폴더, 연결된 Google Drive 폴더 등)로 옮기기로 합의하고, 그 위치를 입력 섹션에 적는다.
- 절차가 바뀌어 툴박스 파일이 낡았다 → 파일과 SKILL.md의 참조를 **같은 커밋에서** 같이 고친다.
- 승인했던 초안이 나중에 나쁜 걸로 드러났다 → 승인 규칙은 그대로 두고, 그걸 잡아냈을 완료 기준을 하나 추가한다.
- 두 job이 템플릿을 같이 쓴다 → 템플릿은 한 job의 `files/`에만 두고, 다른 job은 상대 경로로 링크하며 그렇다고 적는다.
