# 프롬프트 3 — 검증: 완료 기준 연결

## 언제 쓰나
- 툴박스가 생긴 뒤, 이 플레이북을 나 없이 돌리기 전에
- 점검을 **실제로 돌리는 것**을 대신하지 않는다. Claude가 "통과했다"고 주장만 하면 안 되고 직접 돌려야 한다.

## 프롬프트 (그대로 붙여넣고 [대괄호]만 바꾼다)

```
.claude/skills/[job-name]/SKILL.md 에 "완료 기준" 섹션을 넣어줘.

이 일에만 해당하는 점검 항목을 5~10개 써. 각 항목은 네 의견이 아니라 바깥 증거로 확인돼야 해: 원본 파일까지 추적한 숫자, 열리는 링크, 렌더링 스크린샷, 통과하는 테스트, 원문 인용 대조, 개수, 기준 파일과의 값 비교. "명확한", "전문적인", "고품질" 같은 말은 쓰지 마.

앞으로 이 일을 끝낼 때마다, 나한테 보여주기 전에:
1. 모든 항목을 점검해.
2. 실패한 걸 고쳐.
3. 다시 점검해.
4. 항목마다 한 줄로 pass/fail과 쓴 증거를 적어.
5. 확인 못 한 항목은 이유와 함께 따로 적어. 통과로 치지 마.

첫 점검에서 3개 이상 실패하면 결과물을 땜질하지 말고, 절차의 어느 부분이 원인인지 먼저 말해.
```

## 채운 예시 (참고용)

```
.claude/skills/ccu-concrete-quote-draft/SKILL.md 에 "완료 기준" 섹션을 넣어줘.

이 일에만 해당하는 점검 항목을 5~10개 써. 예:
- 견적 단가가 files/price-table.csv 값과 일치 (증거: 셀 값 대조)
- 고객사명·현장명이 문의 메일 원문과 일치 (증거: 원문 인용)
- 합계 = 항목별 금액의 합 (증거: 재계산 결과)
...(이하 위와 동일)
```
