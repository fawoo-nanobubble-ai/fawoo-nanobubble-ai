# fawoo-deeper — 지시를 전문가 기준으로 다시 쓰기

뿌리: Dan McAteer의 `be-ambitious` 스킬(MIT). 그 스킬은 Felix Rieseberg(앤트로픽)가 공유한 프롬프트를 인용해 만들었다. 화우나노텍이 결정 고정, 합격선, 출처 등급, 화우 판단 틀, 분야별 출발점을 더했다. 앤트로픽 공식 스킬이 아니다. 원본 주소와 라이선스는 같은 폴더의 `SOURCE.txt`, `LICENSE`.

## 입력

- `딥퍼` 앞뒤에 붙은 내용이 대상 작업이다. 아무것도 없으면 이 대화에서 가장 최근에 시킨 일을 쓴다. 그것도 없으면 "어떤 일을 깊게 볼까요?" 한 줄만 묻고 멈춘다.
- 모드
  - 기본(`딥퍼`): 다시 쓴 프롬프트를 보여 주고 멈춘다. 사용자가 "응", "이대로", "진행", "돌려"처럼 승인해야 실행한다.
  - 바로(`딥퍼 바로`, `딥퍼 실행`): 다시 쓴 프롬프트를 보여 준 직후 그대로 실행한다.

## 원칙: 크게가 아니라 깊게

- 목표, 범위, 산출물 개수는 그대로 둔다. 바꾸는 것은 기준이다: 더 나은 출처, 더 날카로운 방법, 실제 검증.
- 일을 키우는 제안은 버린다. 꼭 말해야 할 것이면 다시 쓴 프롬프트 **밖에** 한 줄로만 적는다.
- 깊게와 크게의 경계: 그 항목이 **빠지면 결정이 바뀌거나 결과를 믿을 수 없게 되면** 깊게다(넣는다). 안전·법규 위험, 비교 기준(대조군·벤치마크), 과최적화 방지가 여기에 든다. 빠져도 결정과 신뢰가 그대로면 크게다(뺀다).
- 범주 말고 실제 이름을 댄다. "통계 자료"가 아니라 "KOSIS 국가통계포털의 해당 통계표", "논문"이 아니라 "그 논문의 Methods 절".
- 모르는 도구·자료·조항 번호는 지어내지 않는다. `확인 못 함 — 확인 방법: …`으로 적는다.

## 순서

### 0. 결정부터 고정

이 작업 결과를 보고 **누가 무엇을 결정하는가**, 그리고 **어떤 숫자가 나오면 결정이 바뀌는가**를 한 줄로 적는다. 결정권자가 우리가 아니면(제안서를 받는 고객, 심사위원, 담당 부처) 그 사람의 결정으로 고정한다. 대화에서 결정이 안 보이면 가장 그럴듯한 결정을 골라 `[가정]`을 붙인다. 결정과 상관없는 분석은 다시 쓴 프롬프트에서 뺀다.

### 1. 분야 이름

구체적인 분야명 하나. 예: 산업 폐수 처리 공정 경제성, 건설 소재 인증·시험, 시설원예 관수 시험, 암호화폐 선물 시스템 트레이딩, 전파·규제 정책.

### 2. 네 질문

1. **전문가라면 시키지 않아도 하는 것** 2~3개. 유능한 수준과 전문가 수준을 가르는 행동이다. 예: 결정 명시, 기저율(업계 평균값) 확인, 고치기 전 재현, 반론 먼저 쓰기, 대조군 설정, 민감도 분석.
2. **가장 날것의 자료와 그 위치.** 누가 이미 소화한 요약이 아니라 원본이다. 차트가 아니라 데이터셋, 보도자료가 아니라 측정 원기록, 기사가 아니라 법령·고시 원문, 초록이 아니라 특허 청구항·논문 본문, 지표가 아니라 체결 데이터.
3. **방법과 도구.** 이름 붙은 기법·장비·소프트웨어·프레임워크, 그리고 왜 이 작업에 맞는지 한 구절.
4. **바깥 검증과 합격선.** 사용자나 Claude가 아닌 것으로 결과가 맞는지 보인다: 재현, 공인 시험, 원 출처 대조, 실측, 실제 고객 행동, 표본 외 데이터. **무엇이 나오면 통과이고 무엇이 나오면 실패인지** 숫자로 적는다. 합격선 값은 세 가지로 나눠 표시한다.
   - 공인 기준(규격·법령·업계 공식 기준): 출처를 단다.
   - 내가 고른 관례 값(±30% 민감도, 반복 3회 같은 것): `[관례]`를 붙인다.
   - 사용자가 정할 값: `[ ]`로 비워 두고 묻는다.

### 3. 화우 렌즈 — 결정을 바꾸는 축만

- 회사 사업·투자·정책 판단: 아래 네 축 중 결정을 뒤집을 수 있는 축만 넣는다. 다 채우지 않는다.
- 개인 투자·트레이딩: 리스크 축만 쓴다(최대 손실 한도, 포지션 크기, 레버리지).
- 코딩·디자인·편집처럼 실행만 하는 작업: `화우 렌즈: 해당 없음` 한 줄로 끝낸다.

| 축 | 프롬프트에 넣을 질문 |
|---|---|
| 실제 적용 가능성 | 현장 조건(유량·농도·설치 공간·인허가)에서 돌아가는가, 실증은 어느 규모까지 됐나 |
| 수익 구조 | 누가 돈을 내나, 지금 쓰는 대안보다 무엇이 얼마나 싸거나 나은가, 단가·원가·마진 |
| 확장성 | 다른 공장·산업·국가로 옮길 때 바뀌는 변수는 무엇인가 |
| 리스크 | 기술·규제·시장·실행 중 결정을 뒤집을 하나와, 그것이 오고 있다는 신호 |

### 4. 출처 등급

다시 쓴 프롬프트에 "핵심 수치마다 `[등급·기준일]`을 붙여라"를 넣는다.

| 등급 | 무엇 |
|---|---|
| A | 1차: 측정 원기록, 공인 시험 성적서, 법령·고시 원문, 특허 원문, 논문 본문, 거래소 원 데이터 |
| B | 공신력 있는 2차: 정부·국제기구 통계, 리뷰 논문, 표준 문서 |
| C | 기사, 블로그, 업체 홍보물(자사 보도자료 포함), AI 답변 |

결정을 좌우하는 수치가 C등급뿐이면, 결과물 첫머리에 그 사실을 밝히라고 프롬프트에 적는다.

측정·성능 작업(웹 속도, 장비 측정, 백테스트)은 A/B/C 대신 `[출처 · 측정일 · 조건]`을 붙인다. 예: `[CrUX · 2026-11-12 · 모바일 75백분위]`.

**시험 조건 일치 확인**: 인용하는 수치의 시험 대상·조건이 지금 작업 대상과 같은지 본다. 다르면 수치 옆에 차이를 밝힌다. 예: Ca(OH)₂(수산화칼슘) 용액 중화 시험값을 NCC 실폐수 성능처럼 쓰지 않는다.

화우나노텍 자체 수치(화우 관련 작업에만 적용): 이 저장소에서 작업 중이면 `CLAUDE.md` §3 원출처 수치 표가 기준이다. "쓰지 않음" 행은 쓰지 않는다. 표에 없는 사내 수치는 Drive `FAWOO_ARCHIVE` 원자료를 확인하기 전까지 `[미검증]`이다. 저장소 밖(일반 채팅)이면 사용자에게 원자료를 받기 전까지 `[미검증]`으로 둔다.

### 5. 다른 스킬로 넘기기

이 저장소에서 작업 중이면 `CLAUDE.md` §7 스킬 지도에서 맞는 스킬을 찾아, 다시 쓴 프롬프트 첫 줄에 그 스킬을 쓰라고 적는다. 자주 쓰는 연결: 정책·규제 보고서 → `policy-report`, 발표 덱·IR·영업 제안 덱 → `fawoo-motion-deck`, 영상 → `fawoo-video`, 검색·AI 노출 → `fire-your-seo-agency`, 버그·성능 문제 → `systematic-debugging`, 웹 화면 → `impeccable`. 저장소 밖이면 설치된 스킬 목록에서 고른다.

## 분야별 출발점

출발 힌트일 뿐 정답표가 아니다. 이 작업에 맞을 때만 쓰고, 규격·조항 번호는 원문을 확인한 뒤 인용한다.

| 분야 | 날것의 자료 | 방법·도구 | 바깥 검증 |
|---|---|---|---|
| 나노버블 측정 | NTA 측정 원파일(영상·분포 원값)과 측정 조건(희석 배수, 온도, 시료 채취 후 경과 시간) | NTA(나노입자 추적 분석, NanoSight), DLS(동적광산란)로 교차 확인, 무처리수 블랭크 대조 | 제3자 기관 재측정, ISO/TC 281(파인버블 기술위원회) 표준의 용어·보고 항목 대조 |
| 강알칼리 폐수 중화(NCC) | 고객 공정 폐수 실측 시계열(pH, 유량, 알칼리도, 온도)과 성분 분석(황화물 포함 여부) | 같은 실폐수 시료로 CO₂ 대 산(황산·염산) 적정 곡선 비교, 1㎥당 비용 비교. 황화물이 있으면 pH를 낮출 때 H₂S(황화수소)가 생길 수 있어 성분 확인을 먼저 한다 | 파일럿 운전 pH 로그. 방류 경로부터 확인: 직방류면 물환경보전법 배출허용기준 원문, 공공폐수처리시설로 보내면 그 시설의 연계처리 기준 |
| CCU 콘크리트 | 배합표, 시험체 원 데이터, 대조 배합 | 압축강도 시험(KS F 2405), TGA(열중량분석)로 CO₂ 고정량 정량, LCA(전과정평가, ISO 14040/14044) | KOLAS(한국인정기구) 인정 기관 성적서, 대조 배합 대비 강도·CO₂ 차이 |
| 나노버블수 관수 | 시험구 배치도, 처리별 생육·수량 원기록 | 대조구, 반복구, 무작위 배치, 분산분석(ANOVA) | 다른 작기·다른 농가에서 재현, 통계적 유의성 |
| 트레이딩 전략 | 거래소 원 데이터로 직접 만든 봉, 봉 안에서 손절·익절 중 무엇이 먼저 닿았는지 가릴 1분봉이나 체결 데이터, 선물이면 펀딩비 이력. 호가 데이터는 초단타가 아니면 필요 없다 | 수수료·슬리피지·펀딩비를 넣은 백테스트, 워크포워드 분석, 최종 표본 외 구간을 처음에 떼어 두기, 바이앤홀드와 비교 | 소액 실전 결과가 백테스트 범위 안에 드는가, 최대낙폭(MDD) 한도 |
| 정책·규제 | 국가법령정보센터(law.go.kr) 조문, 고시 원문, 국회 의안정보 | 현행 대 개정안 조문 대조표, 해외 입법례 원문 | 소관 부처 해석·질의회신, 조항 번호 인용 정확도 |
| 사업성 분석 | 고객 견적·물량 원자료, 지금 쓰는 대안의 실제 비용 | 단위경제(1단위당 매출−원가), NPV(순현재가치)·IRR(내부수익률)·회수기간, 민감도·시나리오 | 실제 고객의 발주서(PO)나 구매의향서(LOI), 파일럿에서 계약으로 넘어간 비율 |

공개 저장소 주의: 단가·고객사명·미공개 시험 데이터는 결과물에 쓰더라도 저장소에 커밋하지 않는다(`CLAUDE.md` §1).

## 출력 형식

먼저 아래 블록을 쓴다.

```
결정: …  ([가정]이면 표시)
분야: …
전문가라면: …
원자료: … (위치)
방법·도구: …
검증·합격선: 통과 = … / 실패 = …
화우 렌즈: … (또는 해당 없음)
```

이어서 다시 쓴 프롬프트를 **코드블록 하나**로 낸다. 사용자 말투(한국어, 직설)로, 필요한 만큼만 쓴다. 프롬프트의 흐름은 결론 요구 → 원자료에서 시작 → 방법 → 출처 등급 표시 → 검증과 합격선으로 끝맺음이다. 설계를 바꾸는 입력이 빠져 있으면(현물인지 선물인지, 대상 URL, 고객사 방류 경로 같은 것) 맨 앞에 `0. 시작 전에 확인할 것`을 둔다.

마지막 줄: 기본 모드면 `이대로 돌릴까요?` 한 줄. 바로 모드면 묻지 않고 실행한다.

## 쓰지 않을 때

- 단순 사실 질문("KS F 2405가 뭐야?")
- 이미 원자료·방법·검증이 다 적힌 상세한 지시
- 문장 다듬기, 번역, 길이 조절
- 일을 늘리고 싶을 때(범위 확장은 이 스킬의 일이 아니다)

## 예시

사용자: 「CCU 콘크리트 사업성 분석해줘. 딥퍼」

```
결정: 레미콘사 대상 CCU 콘크리트 사업에 들어갈지 [가정]
분야: 건설 소재 사업 경제성 + 소재 인증
전문가라면: 결정을 바꿀 숫자부터 정한다 / 회사 발표 수치를 공인 시험값으로 바꾼다 / 시멘트 단가와 CO₂ 가격의 민감도를 먼저 본다
```
